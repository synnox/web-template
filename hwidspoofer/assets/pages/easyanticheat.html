What is Easy Anti-Cheat?

Easy Anti-Cheat (EAC) is a modular anti-cheat service delivered through Epic Online Services. A studio integrates the EAC SDK and chooses a protection configuration for its own game, which is why Fortnite, Rust, Apex Legends, The Finals, and Dead by Daylight can share the EAC collection layer without sharing one universal publisher ban list.

That breadth creates cross-game exposure. The same PC can present the same board, storage, Windows, network, and security-state values whenever an EAC title initializes. Once a deployment has associated those values with enforcement, another EAC integration can recognize the same composite profile or receive related risk signals. The publisher of each game still decides the account action; an EAC ban in one title does not automatically ban every other EAC title.

TraceX Spoofer addresses the reusable machine profile rather than any one Epic or Steam account. TraceX rewrites its supported identifiers once, keeps those changes persistent, and can then be deleted. There is no per-game preset or resident background process.

How does Easy Anti-Cheat track hardware?

EAC does not publish a field-by-field hardware schema, and integrations can differ. The Windows collection surfaces behind a durable profile are still concrete: `Win32_BaseBoard` exposes the SMBIOS Type 2 baseboard serial, `Win32_DiskDrive` exposes physical-disk descriptors, and `Win32_PhysicalMemory` can expose DIMM identifiers. A client can compare those WMI results with direct SMBIOS table reads and storage properties returned by `IOCTL_STORAGE_QUERY_PROPERTY`; agreement between independent paths is stronger than either value alone.

The OS layer adds `MachineGuid` at `HKLM\SOFTWARE\Microsoft\Cryptography`, volume identifiers, the Windows installation identity, and MAC enumeration across physical and virtual adapters. A reinstall can rotate the Windows values while leaving SMBIOS Type 2 and controller-reported disk serials intact. That mismatch is why reinstalling Windows or changing one NIC does not create a convincingly new composite machine.

TPM and boot trust are separate surfaces. Windows exposes TPM operations through the TPM Base Services (TBS) API, including access paths related to the TPM 2.0 endorsement key, while Secure Boot state describes the verified boot chain. Public EAC material discusses extra security requirements but does not confirm that every integration uploads that key. Treat TPM identity and Secure Boot as possible weighted inputs, not as a single universal EAC serial.

Composite or fuzzy matching explains EAC's resilience better than a mythical master HWID. Board, disk, memory, OS, MAC, TPM, and boot-state signals can be normalized and weighted so routine hardware changes do not erase the older relationship. Because EAC is a shared SDK, the same raw values recur across its roster; publishers administer their own bans, but re-flagging on another EAC title remains possible when enough of the machine profile matches.
